# Domain Docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read relevant decisions in `docs/adr/`.

## Vocabulary

Use the terms defined in `CONTEXT.md` in issue titles, plans, hypotheses, test names, and implementation discussions. If a needed concept is missing, resolve the terminology through the domain-modeling skill before introducing a synonym.

## ADR conflicts

If proposed work contradicts an existing ADR, call out the conflict explicitly and explain whether the ADR should be revisited.

## Layout

Domain documentation uses one root `CONTEXT.md` and system-wide decisions under `docs/adr/`.
